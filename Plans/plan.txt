Project: Sanctum (WIP) — Ethos & Master Plan

Motto: Small. Fast. Efficient. Moddable.

1. Core Ethos & Design Pillars
Microscopic Footprint, Zero Bloat:
No multi-megabyte game engines, no heavy client frameworks, no sprawling asset packs.
The entire web client loads in milliseconds (< 100 KB) and runs smoothly on any browser, low-power laptop, or desktop.
SC-32 Virtual Console Foundation:
Sanctum is architected as the flagship debut cartridge for the **SC-32 Virtual Computing System** (a 32-bit logical fantasy console implemented in Rust with a fixed virtual specification: 32 MiB RAM, 12 MiB VRAM, 3-plane VDP, 8-voice Lanthorn-PSG APU, and `.scart` v1.0 cartridge containers).
1984 Spirit, Modern Feel:
Inspired by the pacing, loot addiction, and dark-fantasy loop of classic dark-fantasy ARPGs, distilled through the blocky, 16-color charm of a PICO-8 / 1984 fantasy console with SANCTUM-48 color engine expansion.
Mouse-First ARPG Controls: Left-click to move, target, and loot; right-click for active skills; 1–4 for belt potions.
Dual-Resolution Clarity:
World Tile Layer (Low-Res Pixel Canvas / Plane 1): 240×144 internal viewport (242×146 canvas with a 2px subpixel scroll margin) upscaled with nearest-neighbor (image-rendering: pixelated) for chunky, evocative retro dungeon tiles, combined with integer tile snapping and fractional GPU CSS translation (translate3d) for silky subpixel camera scrolling.
Entity & UI Overlay Layer (High-DPI Vector Canvas / Planes 2 & 3): Native screen resolution (devicePixelRatio-scaled) overlaid cleanly on top for subpixel-interpolated pawn sprites (players, monsters, projectiles, ground loot), visible held weapons, gear palette tints, health bars, target highlights, razor-sharp floating damage numbers, and Diablo III-style comparative item tooltips.
Canvas-Native ARPG UI Framework:
All core game interfaces (Character Chronicle, Inventory & Paperdoll, Comparative Tooltips, Action Belt, and Modals) are rendered directly to the HiRes canvas overlay via a unified, zero-dependency component framework (`client/systems/ui/`: `UITheme`, `UILayout`, `UIPanel`, `UIButton`, `UISlot`, `UIMeter`, `UIText`, `UIManager`). Zero DOM reflow, pixel-perfect integer snapping, and responsive docking (`TOP_LEFT` / `TOP_RIGHT`).
Authoritative Single Source of Truth (`StatEngine`):
All combat calculations, item stats, primary/secondary scaling, elemental resistances, and comparative deltas are strictly calculated by `shared/StatEngine.js`, ensuring 100% mathematical parity across tooltips, character sheet tabs, and gameplay simulation.
Data-Driven & Moddable:
Engine mechanics (/shared/, /server/, /client/) are strictly decoupled from content (/data/ JSON tables).
Stories, acts, monster stats, skill curves, and item affixes can be expanded or modded without rewriting core simulation code.
Deterministic 32-Bit Simulation:
All procedural dungeon seeds and RNG use 32-bit integer arithmetic (PRNG), ensuring identical map generation across server and clients with minimal network bandwidth (sending a 32-bit seed instead of map data).
2. Gameplay Loop, World Structure & Progression
Campaign Scale & Interconnected World:
Overworld & Dungeons (Interconnected World Graph): An interconnected overworld of distinct biomes (Camp/Town Hub, Highlands, Ruined Courtyard, Graveyard, etc.) with a dynamic Day/Night cycle that transitions seamlessly into multi-floor subterranean dungeons (Crypts, Caverns, Sanctum Depths).
Cell / Chunk Streaming Architecture: Large areas and the interconnected overworld are divided into deterministic spatial cells/chunks (e.g., 32×32 or 40×30 tile cells) streamed and activated on demand around players, giving a continuous, interconnected world feel without loading barriers.
Constrained Biome & Location Generation: Rather than generic random rooms everywhere, each area uses constrained procedural generation tailored to its biome (e.g., road/river/clearing constraints in overworld cells, BSP rooms + doors in keeps/crypts, cellular automata in caverns, fixed set-piece landmarks for boss lairs and town hubs).
Town Hub, Waypoints & Portals: Seamless walk-out transitions from the camp into the overworld, plus Town Portals (TILES.PORTAL_TOWN) and waypoints for quick returns to stash, identify, and restock.
Triple-Tier Progression
Timeline	Mechanics	Player Payoff
Seconds	Kiting, stutter-stepping, targeting packs, belt potions	Tactile combat, chiptune hit feedback, crisp floating damage
Minutes	Level-ups, stat allocation, Normal/Magic/Rare/Unique drops	Noticeable power spikes, build synergies, affix hunting
Runs (NG+)	New Game+ Cycles (Torment tiers)	Exponential monster HP/damage scaling, higher-tier affixes, bigger numbers
Satisfying Damage Scaling

Combat uses multiplicative scaling so early-game hits (8–15) naturally evolve into end-game and NG+ spikes (2,400! CRIT / 15,000! OVERKILL), highlighted with dynamic typography on the high-DPI overlay.

3. Game Modes & Lobby Architecture

To protect the stakes of Permadeath, matchmaking and progression are strictly partitioned:

Classic Mode:
Death respawns the player at the floor entrance with a 10% XP penalty (and restores at least 1 potion).
Shared Classic lobbies (public, private/password, solo, or 6-char invite codes).
Hardcore (Permadeath) Mode:
Isolated Hardcore-only lobbies (no mixing with Classic players).
Server-authoritative death checks prevent client-side disconnect/alt-F4 dodging.
Slain heroes become permanent Fallen Spirits and are immortalized in the server's Hall of Fallen Heroes (with a Hall of Legends schema ready for permanent inductions).
Accounts, Retention & Moderation:
Scrypt-authenticated accounts with a 180-day rolling retention policy (auto-pruning expired accounts and sessions) and a dedicated Moderator Portal (/mod) for account and character administration.
4. Technical & Infrastructure Plan
Dual-Platform Architecture:
1. Native Desktop Runtime: Implemented in Rust as the **SC-32 Virtual Computing System** (`crates/sanctum-core`, `crates/sanctum-vdp`, `crates/sanctum-apu`, `crates/sanctum-scart`, `crates/sanctum-input`). Features embedded QuickJS-NG (ES2020+) executing cartridges sandboxed against `sanctum:engine`, a 3-plane WGPU VDP compositor, an 8-voice Lanthorn-PSG APU, and native OS windowing via `winit`.
2. First-Class Supported Web Edition: Pure browser client (ES Modules, Web Audio, HTML5 Canvas) sharing identical simulation logic and assets without divergence.
Virtual Memory & Hardware Quotas (SC-32):
Fixed virtual machine specification: 32 MiB system RAM, 12 MiB VRAM (6 MiB Plane 1 indexed, 4 MiB Plane 2 stamps, 2 MiB Plane 3 HiRes overlays).
Language & Code Sharing:
Shared /shared/ modules (Constants.js, MathUtils.js, DungeonGen.js, CombatMath.js, StatEngine.js) guarantee identical physics, RNG, and damage math across server and clients.
Modular Client & Server Systems:
Server systems (/server/systems/): GameRoom, DataRegistry, LootGenerator, Database, AuthService, SaveManager, ModService, DemoSeeder.
Client systems (/client/systems/): LightingSystem (merged-wall analytical shadowcasting + 9-band Bayer dither + additive 16-color lights + subpixel sprite/entity stamping), SpriteRegistry (/data/sprites.json hex-grid loader), AudioPSG (Lanthorn-PSG core + Visual SFX Painter engine), MusicPlayer, Renderer, Interpolator, HUDController, InputController, MenuController, and canvas-native UI framework (`client/systems/ui/`).
Detailed documentation of implemented systems lives in SYSTEMS.md and Plans/SC32_COMPLETE_SPECIFICATION.md.
Server-Authoritative Simulation (15 Hz):
Clients send lightweight input intents (MOVE, ATTACK, SKILL, POTION, PICKUP).
Server owns monster AI, hit detection, loot rolls, and death verification, broadcasting compact snapshots at 15 ticks/second.
Homelab & Scaling Strategy:
Designed to run as a tiny Dockerized Node.js service alongside existing homelab workloads (e.g., Jellyfin, RomM) using ~30–50 MB RAM.
Supports Node.js Worker/Cluster multithreading to scale room instances across all 12c/24t Xeon Gold cores if player concurrency grows into the thousands.
Distribution:
Native Desktop: 64-bit Windows portable/installer, Linux AppImage/Steam Runtime binary, and macOS Universal Binary (`x86_64` + `arm64`) targeting Standalone DRM-free, Steam, and GOG.
Web-First + PWA: Instant play from any browser, installable as a standalone desktop window with zero overhead.
Cartridge Packaging: Standalone single-file `.scart` v1.0 binary format containing manifest, scripts, and LZ4-compressed assets.
